# Передача проекта

## Что можно проверить прямо сейчас

1. Установить зависимости, применить миграции, создать каталог и администратора по README.
2. Войти в админку. Во вкладке «Сотрудники» создать сборщика и курьера с привязкой к демо-магазину.
3. Через Swagger запросить OTP для клиента, взять код из серверного лога, войти.
4. Нажать Authorize и вставить accessToken. Добавить адрес и товар в корзину.
5. Получить quote и создать заказ с expectedTotal и Idempotency-Key.
6. Войти сборщиком через отдельный API-сеанс, взять заказ и отметить позиции.
7. Войти курьером, начать смену, взять заказ, забрать после READY и отметить прибытие.
8. Для наличных подтвердить получение оплаты, затем вручение. Для QR предварительно подтвердить тестовый платёж администратором.
9. Проверить историю клиента, историю курьера, заработок и аудит.

Swagger хранит одну авторизацию для вкладки. Для нескольких ролей используйте отдельные профили браузера или curl с разными токенами. Мобильные/React-интерфейсы клиента, сборщика и курьера в этот архив не входят: здесь серверная часть и техническая админка.

## Решения, принятые автономно

| Вопрос      | Принятое решение                                         |
| ----------- | -------------------------------------------------------- |
| База        | PostgreSQL; `pg` и явные SQL-миграции вместо Prisma      |
| Масштаб     | Один модульный сервер, очередь в базе                    |
| SMS         | Лог разработки, код никогда не возвращается в API        |
| Платежи     | Изолированная тестовая имитация; production заблокирован |
| Вход        | Клиент OTP; сотрудники — телефон/пароль                  |
| Валюта      | KGS, целые значения в тыйынах                            |
| Зона        | Радиус вокруг магазина                                   |
| Доставка    | Статическая оценка 20–25 минут                           |
| Замена      | Согласие клиента; QR без увеличения стоимости            |
| Отмена      | До READY; после отправки — согласованный возврат         |
| Курьер      | Один активный заказ; 80 сом за вручение/возврат          |
| Языки       | JSON-поля ru/ky/en, fallback на ru в каталоге            |
| Изображения | HTTPS-ссылки без загрузки файлов                         |
| Поддержка   | Чат через API и SSE, без внешнего мессенджера            |

## Что зависит от владельца сервиса

Для настоящего запуска нужны выбранные SMS- и банковский провайдеры, их документация/учётные данные, тексты документов, реальные товары/цены/остатки, правила доставки и тарифы курьеров. Эти данные нельзя достоверно получить из макета; они не выдуманы как готовые интеграции.

Следующие изменения после выбора провайдеров: реальные адаптеры, удаление запрета production только после проверки адаптеров, подключение карт, push и хранилища изображений, автоматизация чеков при необходимости. Правила возврата полученных наличных и увеличения суммы предоплаченного заказа нужно определить отдельно.

## Проверки проекта

Интеграционные тесты проверяют не форму кода, а поведение: одноразовые OTP и лимиты, ротацию токенов, разделение ролей, чужие адреса/заказы, полный наличный заказ, резерв последнего товара, конкурирующие назначения, повторное оформление, изменения цены, подпись/повторы оплаты, позднюю оплату, таймеры, исключения, замену и частичный возврат, возврат товара, акции, поддержку и блокировку сотрудника.

Тестовая схема PostgreSQL создаётся автоматически через `TEST_DATABASE_URL`. PGlite доступна без установки базы; её транзакции сериализованы, поэтому многосоединённую конкуренцию нужно отдельно проверять на обычной PostgreSQL.

## Сборка и изменение документации

```bash
node scripts/openapi.mjs
npm run check
npm run build
npm test
```

Исходник спецификации — `scripts/openapi.mjs`. Обновляйте его вместе с контрактом API и перегенерируйте `docs/openapi.json`. Применённую SQL-миграцию не редактируйте: добавляйте новый файл. Секреты и `.env` не включены в архив.
